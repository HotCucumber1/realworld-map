# World Explorer

Android-приложение для исследования реального мира. Вы ходите с телефоном — приложение записывает GPS-трек и постепенно «открывает» настоящую карту там, где вы побывали, как туман войны в играх.

- **Fog of War** — карта скрыта облаками (или тёмным слоем); исследованные места открываются с мягкими краями.
- **Explorer Map** — вся карта видна, исследованное подсвечено цветом и контуром.

Оба режима рисуют одни и те же данные. Переключение меняет только видимость слоёв, а треки и территория остаются как есть.

## 2. Архитектура и структура проекта

Clean Architecture + MVVM, три Gradle-модуля:

```
domain/   чистый Kotlin (без Android): модели, контракты репозиториев, use cases,
          гео-алгоритмы (сетка, контуры, сглаживание), фильтр GPS
data/     Android library: Room, DataStore, геолокация (Fused/LocationManager),
          backup (ZIP), синхронизация (Supabase/OkHttp, WorkManager), Hilt-модули
app/      UI на Jetpack Compose + Material 3, ViewModel'и, Navigation Compose,
          адаптер карты MapLibre, foreground service записи, DI приложения
supabase/ schema.sql (таблицы, триггеры, RLS) и verify_schema.py
```

Зависимости направлены внутрь: `app → data → domain`. Модуль `domain` — обычный JVM-модуль, поэтому импортировать Android, Room или карту в бизнес-логику невозможно физически. Подробнее — в [ARCHITECTURE.md](ARCHITECTURE.md).

`compileSdk = 37`, `targetSdk = 36`, `minSdk = 26`. Почему так:
- **minSdk 26** (Android 8): каналы уведомлений, современная модель foreground service, adaptive icons, `java.time` без desugaring; покрывает подавляющее большинство устройств.
- **targetSdk 36** (Android 16): поведение foreground service типа `location`, фоновых ограничений и edge-to-edge проверено именно для него. Переход на 37 — отдельная задача после проверки изменений поведения Android 17.

## 4. Как открыть проект в Android Studio

1. `File → Open…` → выберите корень репозитория.
2. Studio сама создаст `local.properties` с `sdk.dir`. Если нет, создайте его вручную: `sdk.dir=/путь/к/Android/Sdk`.
3. Дождитесь Gradle Sync. Если SDK Platform 37 не установлена, Studio предложит её скачать.
4. Запуск: конфигурация `app` → устройство → Run.

> **Корпоративный прокси.** JVM не берёт системный прокси из переменных окружения. Пропишите его в `~/.gradle/gradle.properties` (`systemProp.https.proxyHost=…`, `systemProp.https.proxyPort=…`) или передайте через `JAVA_TOOL_OPTIONS`. Если прокси подменяет TLS-сертификаты своим корневым CA, debug-сборка доверяет пользовательским CA, установленным на устройстве (см. `res/xml/network_security_config.xml`, блок `debug-overrides`). Release-сборка им не доверяет.

## 9. Установка APK на телефон через ADB

1. На телефоне: «Настройки → О телефоне» → 7 раз нажмите «Номер сборки», затем «Для разработчиков → Отладка по USB».
2. Подключите кабель и подтвердите отладку на телефоне.
3. Выполните:


Debug-сборка ставится рядом с release (`applicationId` = `com.worldexplorer.app.debug`).

## 11. Картографический провайдер

По умолчанию используются **OpenFreeMap**: бесплатные векторные тайлы на данных OpenStreetMap, без ключа и регистрации. Атрибуция видна по кнопке «i» на карте и в настройках. В «Настройки → Стиль карты» можно выбрать:

| Стиль | Источник | Ограничения |
|---|---|---|
| Liberty / Positron / Bright | `https://tiles.openfreemap.org/styles/…` | бесплатно, без ключа |
| OpenStreetMap (растровый) | `tile.openstreetmap.org` | [политика использования OSMF](https://operations.osmfoundation.org/policies/tiles/): только лёгкое личное использование, без массовой загрузки. Приложение передаёт собственный User-Agent |
| Свой стиль по URL | любой стиль MapLibre (`https://…/style.json`) | если провайдеру нужен ключ, он указывается прямо в URL стиля (например MapTiler: `https://api.maptiler.com/maps/streets-v2/style.json?key=ВАШ_КЛЮЧ`) |

Карта подгружает только тайлы видимой области. Просмотренные тайлы MapLibre кэширует на диске (~50 МБ), поэтому без сети видны уже посещённые места.

## 12. Облачный backend (Supabase)

Кратко (подробно — в [SYNC.md](SYNC.md)):

1. Создайте проект на https://supabase.com (бесплатный тариф).
2. SQL Editor → вставьте и выполните [`supabase/schema.sql`](supabase/schema.sql).
3. Authentication → Providers → Email должен быть включён. Подтверждение e-mail — по желанию.
4. Project Settings → API: скопируйте **Project URL** и **anon public key**.
5. Добавьте в `local.properties` (файл не попадает в Git):
   ```properties
   supabase.url=https://xxxxxxxx.supabase.co
   supabase.anonKey=eyJhbGciOi...
   ```
   Можно вместо этого задать переменные окружения `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
6. Пересоберите: `./gradlew assembleDebug`. В приложении: «Настройки → Облачная синхронизация» → создайте аккаунт или войдите → включите «Синхронизировать мои данные».

Без этих шагов приложение работает полностью локально, а экран облака объясняет, как его настроить.

## 13. Разрешения

| Разрешение | Зачем | Обязательно |
|---|---|---|
| `ACCESS_FINE_LOCATION` | точная позиция для записи и маркера | да, для записи |
| `ACCESS_COARSE_LOCATION` | система может выдать только приблизительную позицию; тогда точность хуже | — |
| `ACCESS_BACKGROUND_LOCATION` («Разрешить всегда») | системе нужно разрешение, чтобы перезапустить прерванную запись без открытия приложения | нет |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION` | запись в foreground service типа `location` (Android 14+) | да |
| `POST_NOTIFICATIONS` (Android 13+) | постоянное уведомление о записи с кнопкой «Остановить» | рекомендуется |
| `INTERNET`, `ACCESS_NETWORK_STATE` | тайлы карты, синхронизация, индикатор «нет сети» | да |

Хранилище не запрашивается: экспорт и импорт идут через системный выбор файла (Storage Access Framework).

## 14. Как включить фоновое отслеживание

1. Выдайте доступ к геолокации (onboarding или кнопка на карте) и разрешите уведомления.
2. Нажмите круглую кнопку записи на карте. Появится уведомление «Идёт запись маршрута».
3. Теперь экран можно выключить, а приложение свернуть: запись продолжится, пока вы не нажмёте «Остановить» в приложении или в уведомлении.
4. Для надёжности: «Настройки → Оптимизация батареи» → исключите приложение. По желанию: «Фоновый доступ к геолокации → Разрешить всегда».

Если процесс убит (нехватка памяти, сбой, перезагрузка), при следующем открытии приложение продолжит тот же трек, если с последней точки прошло меньше 6 часов. Иначе трек закрывается как «Прервана». Скрытый автозапуск после перезагрузки не делается намеренно.

## 15. Ограничения энергосбережения

- Android не гарантирует непрерывный GPS. В Doze и у агрессивных оболочек (Xiaomi/MIUI/HyperOS, Huawei/EMUI, Samsung One UI «спящие приложения», OPPO/realme/ColorOS, Vivo) foreground service могут останавливать. См. https://dontkillmyapp.com.
- Внутри зданий, в тоннелях и метро сигнала нет. Уведомление показывает «Нет сигнала GPS», запись продолжается, когда сигнал вернётся.
- Если геолокацию выключить в системе, запись ждёт её включения. Об этом сообщают уведомление и баннер.
- Если отозвать разрешение во время записи, Android убивает процесс. При следующем запуске трек закрывается как прерванный.
- Расход батареи зависит от профиля: Точный — 2 с, Сбалансированный — 4 с, Экономный — 10 с; на месте интервал автоматически увеличивается в 3–4 раза.

## 16. Экспорт и импорт

«Настройки → Экспорт и импорт».
- **Экспортировать всё** — системный диалог сохранения → ZIP (`world-explorer-ГГГГММДД-ЧЧММ.zip`) со всеми маршрутами, точками, территорией и настройками.
- **Импортировать** — выберите файл. Он полностью проверяется до любых изменений: структура, версия, контрольные суммы, координаты, ссылки. Затем на выбор:
  - **Объединить**: добавить недостающее; совпадающие маршруты берутся в более новой версии, дубликаты точек игнорируются;
  - **Заменить**: требует подтверждения галочкой. Перед заменой копия текущих данных сохраняется во внутреннюю память (хранятся 3 последние), и предлагается экспортировать их отдельно.
- При ошибке импорт откатывается целиком: данные остаются как были.

Формат описан в [BACKUP_FORMAT.md](BACKUP_FORMAT.md).

## 18. Алгоритм исследования территории (кратко)

1. Мир разбит на неизменную географическую сетку с шагом 1/20000° (≈5,6 м по широте). Ячейка — пара целых чисел (row, col). Сетка не зависит от zoom и экрана.
2. Для каждой принятой GPS-точки отмечаются все ячейки, центр которых лежит в радиусе R (по умолчанию 20 м). Запись идёт в одной транзакции с точкой, `INSERT OR IGNORE`, так что повторные проходы не создают дубликатов.
3. Для отрисовки берётся только видимое окно (+50 % запаса). При мелком масштабе используются заранее агрегированные уровни 2⁴ и 2⁸ ячеек, поэтому работа ограничена (≤768×768 ячеек) при любом zoom.
4. Контур объединения ячеек трассируется в кольца, вложенность (дыры, острова) определяется за линейное время по компонентам связности. Кольца сглаживаются (Chaikin), край тумана размывается.
5. Туман — непрозрачный полигон «весь мир минус исследованное». При обновлении он двойной буферизацией защищён от моментов, когда маска не нарисована.

Подробно, с обоснованием, — в [ARCHITECTURE.md](ARCHITECTURE.md#fog-of-war).

## 19. Как добавить новые настройки и функции

**Новая настройка:**
1. Поле в `domain/model/Settings.kt` (`AppSettings`) со значением по умолчанию.
2. Ключ и чтение/запись в `data/settings/SettingsRepositoryImpl.kt`.
3. Если её разумно переносить на другой телефон — поле в `BackupSettings` (`data/backup/BackupFormat.kt`) и в `applySettings`. Новые поля добавляйте со значением по умолчанию, чтобы старые копии читались.
4. Событие в `SettingsEvent`, обработка в `SettingsViewModel`, UI в `SettingsScreen`.
5. Тест в `SettingsRepositoryImplTest` / `SettingsViewModelTest`.

**Новая функция:** доменная логика и use case — в `domain` (с unit-тестом на fake из `domain/src/testFixtures`), реализация хранения/сети — в `data`, экран — `app/feature/<имя>` (ViewModel со `StateFlow` immutable-состояния + stateless Composable), маршрут — в `AppNavHost`.

**Изменение схемы БД:** увеличьте `WorldExplorerDatabase.VERSION`, добавьте `Migration` в `DatabaseMigrations.ALL` (destructive migration не используется), закоммитьте новую схему из `data/schemas/`. `MigrationsTest` проверит, что цепочка миграций полна.

## 20. Известные ограничения MVP

- **Облачная синхронизация не проверена против настоящего Supabase**: credentials в среде разработки не было. Проверены клиент против MockWebServer, движок синхронизации на двух БД с fake backend и SQL-схема на реальном PostgreSQL 16 (RLS, триггеры, удаление аккаунта). Первый запуск с вашим проектом — шаг ручной проверки.
- Маршрут выгружается в облако после окончания записи, территория — сразу.
- Сетка равноугольная (в градусах), поэтому на высоких широтах ячейки уже: на 55° ≈ 5,6×3,2 м. Это увеличивает число ячеек, но не влияет на корректность. Выше ±85,05° (предел Web Mercator) отмечается только ячейка самой точки.
- При мелком масштабе исследованное показывается «с запасом»: ячейка 2^k считается открытой, если открыта любая её часть.
- При быстром перемещении карты исследованное за пределами запаса в 50 % открывается через ~0,1 с после остановки камеры, до этого там остаётся туман.
- Пересечение антимеридиана поддерживается (окна делятся надвое), но на стыке двух окон в 180° возможен тонкий шов.
- Изменение радиуса применяется к новым точкам: уже открытая территория не пересчитывается (радиус хранится в каждой точке, пересчёт возможен в будущем).
- Удаление отдельных маршрутов пока не реализовано.
- На некоторых оболочках Android фоновую запись могут останавливать (раздел 15).
- `targetSdk = 36`: переход на 37 требует проверки изменений поведения Android 17.
